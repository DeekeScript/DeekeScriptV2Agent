# 开发前先写清进度模型

在任何列表、搜索结果、半屏、推荐流里循环时：**先想清楚怎么前进，再写循环。** 禁止套用「处理一条 → 立刻滑动」。

相关：[`app-survey.md`](./app-survey.md)、[`skip-on-item-failure.md`](./skip-on-item-failure.md)、[`segment-test.md`](./segment-test.md)、[`task-template.md`](../task-template.md)。

## 硬规则（MUST）

1. **写循环前必须书面回答下方自问表**（写进回复）。答不出 = 调研没完，禁止落盘主循环。
2. **滚动只服务当前看不见的条目。** 当前屏已露出、尚未处理（或尚未判定不合格）的目标，必须先处理完。
3. **进度单位是一条；前进方式由视口决定。** 同屏还有下一条 → 返回后点那一条；同屏没有了 → 才滚动。
4. 从子页 / 半屏返回后：**重新 find 当前屏**，用已处理身份跳过，再取下一条可见目标。禁止「回来永远点第一个」或「回来立刻滑动」。

## 开发前必须自问

任何第三方 App 循环，先对**当前屏节点**问：

| 问自己 | 怎么得到答案 | 答错会怎样 |
|--------|----------------|------------|
| 当前屏同时能露出几条目标？ | `snapshot` / `find` 后**数**，不要凭印象 | 处理 1 条就滑，同屏其余被划掉 |
| 滚动何时才允许？ | 仅当当前屏已无「未处理且合格」的目标 | 把滚动当成「下一条」的唯一手段 |
| 列表有几层？缩进 / 更靠里 / 可展开的还算目标吗？ | 对比两类 `bounds`；需求没点名子层则排除 | 把子项当父项 |
| 对象有几种外观？ | 原话里的并列词，每种打开一次 | 只做最好找的一种 |
| 从子页返回后，如何认「下一条」？ | 已处理集合 + 再扫当前屏 | 总是第一条，或总是滑走整屏 |
| 本条失败时丢掉的是这一条还是这一屏？ | skip 这一条，同屏其余仍在 | 失败也滑动，邻居一起没了 |

**自测：** 当前屏 `count >= 2` 时，循环不滚动能否处理第 2 条？不能 → 模型是错的。

## 视口类型（自己归类）

看「一屏有几条完整目标」：

| 视口 | 特征 | 处理完一条之后 |
|------|------|----------------|
| 一屏一条 | 一条占满操作区 | 滑动到下一条 |
| 一屏多条 | 多列、卡片墙、列表 | **先耗尽当前屏**，再滚动加载 |
| 半屏列表 | 从底部/侧边弹出的列表 | 同上；手势落在列表区域，不要滑到页面铬条 |

「前进到下一条」不是无条件 `swipe`。一屏多条时，下一条往往还在当前屏上。

## 循环骨架（一屏多条）

```javascript
var seen = [];
while (未到时长或数量上限) {
  var item = findNextVisibleNotIn(seen);
  if (!item) {
    scrollToLoadMore();
    continue;
  }
  seen.push(item.id);
  openAndHandle(item);
}
```

从子页返回后必须重新 `find`。不要在 `openAndHandle` 之后无条件滑动。
