# 分段测试（禁止用整段任务当第一个测试）

开发中测的是**一个动作**；整段 `run-file` 只做**验收**。

「片段 `run` 再 `run-file`（数量=1）」若理解成少跑几条的整段任务，失败时分不清是哪一步错。

相关：[`app-survey.md`](./app-survey.md)、[`progress-model.md`](./progress-model.md)、[`device.md`](../../00-core/device.md)、[`stale-node-after-click.md`](./stale-node-after-click.md)。

## 两层（不要混）

| 层 | 何时 | 怎么做 | 通过标准 |
|----|------|--------|----------|
| **分段** | 刚写完或刚改完一个动作 | 手机**已经停在**该动作所需页面，`run` **只执行该动作** | 该动作的节点 logs + 界面变化符合预期 |
| **验收** | 清单上的分段都过了 | `write` 后 `run-file`（可用数量=1）；调研清单里的每种形态各至少一条 | 串联后仍正确，父子层没有串台 |

禁止：分段没过就 `run-file`；用「整段数量=1」代替单步测试。

## 硬规则（MUST）

1. **一个动作一段 `run`。** 不要为了测后面的动作而从头重跑导航。
2. **分段的前置是停在目标页。** 调研时停在那，或先跑一段只负责导航的 `run`。再调用业务方法。
3. **分段失败只修这一段**，`write` 后只重测这一段。
4. **验收才拼循环。** 覆盖调研清单里的每种形态，不是只跑碰巧打开的那一种。
5. 分段 logs 必须证明点对了对象：区域、`bounds`、是否子层，而不是「点了某个同名按钮」。

## 怎么切（按动作，不按产品）

从需求里的动词拆段。每一段：先停在该动词发生的那一页，再只做这一件事。

| 这类动作 | 手机先停在 | 这段只做 | 不要夹带 |
|----------|------------|----------|----------|
| 进入列表 / 搜索 | 目标 App 可出发页 | 到达列表并打印互斥节点 | 不要打开条目 |
| 打开一条 | 列表上目标可见 | 进入详情，打印这是清单里的哪一种形态 | 不要做条目内操作 |
| 条目内操作（赞、评、关、藏…） | 已在该条详情或半屏 | 只做这一个操作，再读结果态 | 不要进主页、不要下一条 |
| 区分父项 / 子层 | 能同时看到两层的页面 | 打印两类 `bounds`，确认过滤 | 不要对子层执行父项目标动作 |
| 取下一条 | 刚处理完一条并已回到列表 | 不滚动，再 `find` 下一条可见未处理 | 立刻滑动 |

输入类分段顺序见 [`comment-input.md`](../../03-recipes/comment-input.md)。

## 自检

- [ ] 每个业务动作都有独立 `run` logs，且当时停在该页
- [ ] 没有用整段 `run-file` 作为某动作的第一次测试
- [ ] 每种形态的分段和验收都至少各一次
- [ ] 有子层时，有「排除子层」的分段 logs
- [ ] 一屏多条时，有「不滚动处理第 2 条」的分段 logs
